HTW Berlin · Gruppenprojekt

Prozessautomatisierung mit Camunda 7

Für das fiktive, nachhaltige Verpackungsunternehmen PackToTheRoots haben wir zwei Geschäftsprozesse in BPMN modelliert und mit der Process Engine Camunda 7 automatisiert.

Worum es geht

  • Auftragsprozess: Ein Handelskunde bestellt Verpackungen für eine Kampagne, mit festem Budget und FSC-zertifizierten Materialien.
  • Reklamationsprozess: Reklamationen werden mit einer Ticketnummer erfasst und bearbeitet. Benachrichtigungen gehen automatisch per E-Mail raus.

Mein Beitrag

  • Zwei Node.js-Worker für Camunda External Tasks lauffähig gemacht und paketiert: SMTP mit STARTTLS, Topic-Subscriptions und Authentifizierung an der Camunda REST-API
  • Fehler in einem Execution Listener behoben, bei dem die Empfängeradresse für E-Mails falsch gesetzt war
  • Für die Transportbuchung eine RPA-Integration mit UiPath konzipiert: erst die Dateneingabe durch einen Menschen, danach ein automatischer Service Task
  • Formularfelder per Python-Skript vereinheitlicht und alle Prozessschritte auf Deutsch dokumentiert
  • Entwicklerdokumentation, Formulartabellen für alle 12 User Tasks und Skripte für Video-Tutorials erstellt

Abschluss

Abschlusspräsentation mit dem durchgespielten Kundenszenario, Lessons Learned zu Teamarbeit und Projektmanagement sowie einer Aufwandsabrechnung pro Teammitglied.

  • Camunda 7
  • BPMN 2.0
  • Node.js
  • REST-API
  • SMTP
  • UiPath
  • Python

Gym-Tracker: Webanwendung für Trainingspläne

Eine Webanwendung, mit der man sein Training plant und protokolliert, sodass Fortschritte über die Zeit sichtbar werden.

Funktionen

  • Workouts anlegen und Übungen aus einer Bibliothek hinzufügen
  • Eigene Übungen erstellen
  • Workout starten und pro Satz Gewicht und Wiederholungen erfassen
  • Trainingsverlauf und Kalender
  • Login, jeder Nutzer sieht nur seine eigenen Daten

Mein Beitrag

  • Datenmodell für Übungen und Workouts im Backend angelegt (Entities, Repositories, Services)
  • Übungssuche über eine externe Übungs-API, im Backend und im Frontend
  • Login mit Auth0: Das Backend prüft JWTs, damit jeder Nutzer nur seine eigenen Workouts sieht
  • Unit-Tests für die Kernfunktionen rund um Workouts und Übungen
  • Frontend an die REST-API angebunden und Dashboard überarbeitet
  • Dockerfile für das Deployment auf Render erstellt

Aufbau

Frontend mit Vue 3 und TypeScript, REST-API mit Spring Boot in Java, PostgreSQL als Datenbank. Tests und Builds laufen automatisch über GitHub Actions, das Deployment per Docker auf Render.

  • Java
  • Spring Boot
  • PostgreSQL
  • Vue 3
  • TypeScript
  • Auth0
  • Docker
  • GitHub Actions
  • JUnit

DatheDungeon: Dungeon Crawler in Java

Ein 2D-Dungeon-Crawler, dessen Schauplatz unsere eigene Schule ist. Flure und Klassenräume sind dem Dathe-Gymnasium nachempfunden.

Kampf im Geografieraum, Gespräch mit einem Lehrer, Startbildschirm. Zum Vergrößern anklicken.

Die Story

Die Schule ist voller Monster, die durch ein Ritual entstanden sind. Raum für Raum muss man sie vertreiben, um das Ritual zu brechen. Wer es schafft, bekommt seinen Abschluss. Wer verliert, liest: „NO ALLGEMEINE HOCHSCHULREIFE FOR YOU IN THIS LIFE.“

Gameplay

  • 17 Räume, die nacheinander freigespielt werden
  • Zu Beginn erklärt ein Lehrer die Steuerung, an einer Trainingspuppe übt man den Angriff
  • Türen öffnen sich nur mit Schlüssel, beim Betreten eines Raums erscheinen die Monster
  • Gegenstände wie Stiefel machen schneller, Herzen zeigen das Leben an
  • Intro- und Outro-Animation, Musik und Soundeffekte

Mein Beitrag

  • Spiellogik: wie sich Spielfigur, Monster und Räume verhalten
  • Gameplay-Design: Ablauf, Schwierigkeit und Fortschritt durch die Räume
  • Character Design: Gestaltung der Spielfiguren

Umsetzung

Java mit Swing, eigener Game Loop mit 60 Bildern pro Sekunde, eine Kachelkarte mit 76 × 61 Feldern, Kollisionserkennung, Sprite-Animationen und Spielzustände wie Titelbildschirm, Dialog, Pause und Game Over.

  • Java
  • Java Swing
  • 2D-Grafik
  • Pixel Art
  • Teamarbeit
